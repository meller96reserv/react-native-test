# Руководство по реализации

## Цель

Создать небольшое, аккуратное Expo-приложение с последовательностью onboarding → paywall →
главный экран и сохранением эмулированной подписки между запусками.

## Роли

Роли описывают зоны ответственности при последовательной работе над проектом. Они не требуют
отдельных процессов или исполнителей.

### Архитектор

- сверяет решения с `todo.txt` и `docs/architecture.md`;
- сохраняет модульные границы и направляет зависимости от UI к доменной логике;
- не добавляет библиотеку без измеримой пользы для текущего масштаба приложения;
- контролирует лимит: каждый файл с кодом — не более 500 строк.

### Expo / React Native разработчик

- реализует задачи строго в порядке `docs/todo.md`;
- отделяет экраны, компоненты, состояние, хранение, типы, дизайн-токены и стили;
- использует строгий TypeScript, стабильные props и мемоизацию там, где она уменьшает работу;
- учитывает доступность, safe area, разные размеры экранов и состояния загрузки/ошибки.

### Тестировщик

- проверяет холодный запуск без подписки и с сохранённой подпиской;
- проверяет выбор тарифов, эмуляцию покупки и восстановление после перезапуска;
- запускает статические проверки и автоматические тесты;
- проверяет основные сценарии на Android и iOS либо документирует ограничения среды.

### Ревьюер производительности и качества

- ищет лишние ререндеры, нестабильные callbacks и тяжёлую работу в render;
- проверяет, что списки и анимации соответствуют реальной нагрузке;
- контролирует отсутствие секретов, debug-кода и ненужных зависимостей;
- сверяет готовый результат с README и чек-листом.

## Стратегия декомпозиции

1. Зафиксировать архитектуру и критерии готовности до написания кода.
2. Создать минимальный Expo/TypeScript каркас и quality gates.
3. Реализовать фундамент: токены, UI-kit, persistence и session state.
4. Собрать маршрутизацию и стартовую гидратацию без мигания неверного экрана.
5. Последовательно реализовать onboarding, paywall и home.
6. Покрыть критическую логику тестами и пройти ручную приёмку.
7. Подготовить README и сценарий демонстрации работы «разработчик + AI».

## Правила работы

- Источник требований: `todo.txt`; источник плана: `docs/todo.md`.
- После каждого законченного шага обновлять соответствующий checkbox в `docs/todo.md`.
- Не отмечать пункт готовым до проверки указанного результата.
- Не смешивать несвязанные изменения в одном шаге.
- Сначала выбирать платформенные и Expo API; зависимость добавлять только с обоснованием.
- Не использовать `FlatList` для больших списков: при появлении такого сценария оценить
  `@shopify/flash-list`. Для небольшого статичного контента не виртуализировать без нужды.
- `useMemo`, `useCallback` и `React.memo` применять по измеримой границе ререндера, а не
  механически: лишняя мемоизация тоже усложняет код и расходует память.
- Никогда не хранить реальные платёжные данные. Покупка в задании — локальная эмуляция.
- Перед завершением шага запускать релевантные проверки из `docs/todo.md`.

## Definition of Done

- Все обязательные пункты `docs/todo.md` отмечены и фактически проверены.
- Ни один файл с кодом не превышает 500 строк.
- TypeScript, lint и тесты проходят без ошибок.
- Подписка сохраняется и корректно меняет стартовый маршрут после перезапуска.
- Нет заметного мигания onboarding/paywall во время чтения сохранённого состояния.
- README описывает запуск, архитектуру, структуру и возможные улучшения.
- Подготовлены инструкции для записи скринкаста; публикация видео и GitHub остаётся действием
  владельца проекта.
